# منصة الفواتير وروابط السداد — إيقاع الحياة

توجد إدارة الفواتير داخل المتجر في المسار `/admin/invoices`. هذه المساحة محمية بتسجيل دخول المالك، وتتيح إنشاء فاتورة ورابط عام بصيغة `/pay/{publicId}`، ونسخ الرابط لإرساله للعميل. لا يخزن المتجر أرقام البطاقات أو رموز التحقق.

## التشغيل الحالي

تنشئ المنصة الفاتورة وتدير مرجعها وقيمتها بالريال السعودي وحالة الرابط وتاريخ انتهاء صلاحيته. ولأن شركة تشغيل الدفع لم تُحدد بعد، تعرض صفحة العميل بوضوح أن رابط الدفع قيد التجهيز ولا تطلب منه إدخال أي بيانات حساسة.

عند ربط مشغّل دفع مرخّص لاحقًا، ينفذ محول المشغّل الخطوات التالية: ينشئ فاتورة عند المشغّل، ويحفظ معرف الفاتورة ورابط صفحة الدفع المستضافة، ثم يتحقق من توقيع إشعار السداد الوارد قبل تحديث حالة الفاتورة محليًا إلى `paid`. في الوضع الحالي، يمنع المحول الافتراضي إنشاء أي صفحة دفع أو قبول أي إشعار سداد حتى تركيب محول الشركة ومفاتيحها السرية على الخادم.

| العنصر | المسار | الحماية |
|---|---|---|
| إدارة الفواتير | `/admin/invoices` | تسجيل دخول المالك وصلاحية `admin` |
| صفحة فاتورة العميل | `/pay/{publicId}` | رابط عام محدود البيانات |
| إنشاء فاتورة من نظام خارجي | `POST /api/payment-links/v1/invoices` | `Bearer` أو `X-API-Key` |
| قراءة حالة فاتورة | `GET /api/payment-links/v1/invoices/{reference}` | `Bearer` أو `X-API-Key` |
| إشعار شركة التشغيل | `POST /api/payment-links/v1/callbacks/{provider}` | تحقق توقيع داخل محول الشركة فقط |

## استخدام واجهة الأنظمة الخارجية

أنشئ مفتاحًا جديدًا من قسم **مفاتيح الأنظمة الجديدة** في لوحة الفواتير، واحفظ القيمة التي تظهر مرة واحدة فقط في إعدادات النظام الخارجي. يُخزَّن في قاعدة البيانات بصيغة تجزئة أحادية الاتجاه، ويظهر في اللوحة بادئته فقط.

### إنشاء فاتورة

```http
POST /api/payment-links/v1/invoices
Authorization: Bearer ih_live_...
Content-Type: application/json

{
  "customer_name": "اسم العميل",
  "customer_email": "customer@example.com",
  "customer_phone": "0500000000",
  "description": "وصف المنتج أو الخدمة",
  "amount": 1250.50,
  "expires_in_days": 7,
  "metadata": {
    "external_order_id": "ORD-1001"
  }
}
```

تتضمن الاستجابة مرجع الفاتورة ورابطها العام وحالة جاهزية الدفع. تكون `payment_ready` بقيمة `false` إلى أن يكتمل ربط شركة التشغيل.

```json
{
  "id": "IH-20260902-ABC123",
  "status": "draft",
  "amount": 1250.5,
  "currency": "SAR",
  "payment_url": "https://ayqaealhayaa.sa/pay/inv_...",
  "payment_ready": false
}
```

## متطلبات ربط شركة التشغيل لاحقًا

تحتاج مرحلة التفعيل إلى اسم المشغّل وبيئة الحساب (تجريبية أو إنتاجية) ومفاتيح API ورابط إشعار الدفع أو السر المشترك لتوقيعه. يجب حفظ هذه القيم على الخادم فقط وعدم وضعها في ملفات الواجهة أو رسائل واتساب. بعد التفعيل، يجب اختبار فاتورة تجريبية والتحقق من أن الإشعار الموقّع وحده هو الذي يغيّر حالة الدفع.
