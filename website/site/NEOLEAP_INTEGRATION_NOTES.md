# ملاحظات تكامل Neoleap

## الحالة الحالية

- طلب المالك استبدال CCAvenue ببوابة Neoleap داخل متجر Manus.
- أظهرت المادة التي قدمها المالك وجود بيئة اختبار وبوابة دفع مستضافة، لكن الصورة تضمنت بيانات حساسة. لم تُنسخ القيم ولم تُحفظ ولم تُستخدم.
- تعطّل CCAvenue الحي في متجر Manus أثناء إعداد مسار Neoleap الاختباري.

## نتيجة التحقق الخارجي

- تؤكد صفحة Neoleap العامة أنها تقدم خدمة بوابة دفع إلكتروني، لكنها لا تعرض توثيق API أو مواصفات توقيع الطلبات اللازمة لتنفيذ تكامل خادمي آمن.
- محاولة الوصول إلى رابط بوابة التاجر الخارجي المشار إليه في المادة المقدمة أعادت استجابة 404 من دون دليل تكامل عام.
- لا يجوز تخمين معلمات إنشاء جلسة الدفع أو خوارزمية التوقيع أو رابط الإشعار من صورة أو من صفحة تسويقية.

## ما يؤكده دليل المستخدم المرفوع

- الدليل هو **Neoleap(ARB) E-Commerce Payment Gateway 3.3.1 — User Manual**، بتاريخ نشر مارس 2025.
- يذكر الدليل أن منصة التاجر هي `https://securepayments.neoleap.com.sa/misrpts/merchant.htm`، وليس المسار المختلف الذي ظهر في الصورة المرفوعة سابقًا.
- يصف الدليل قسمًا لتنزيل ملفات الموارد وإضافات التكامل وتدوير مفتاح الجهاز، إضافةً إلى معاينة صفحة الدفع وإدارة الفواتير المخصصة.
- الدليل المستخدم تشغيلي للتاجر ولا يحتوي في الصفحات المتاحة على مواصفات طلب API أو حقول توقيع أو عقد إشعار خادمي كافية لبناء دمج برمجي موثوق.
- أمثلة الاعتمادات الواردة في الدليل أمثلة توضيحية فقط ولا تُستخدم في أي بيئة أو اختبار.

## المطلوب من Neoleap

1. دليل التكامل الرسمي لبيئة الاختبار أو رابط بوابة المطورين.
2. آلية إنشاء جلسة الدفع المستضافة، وحقول الطلب الإلزامية، وخوارزمية التوقيع.
3. عناوين العودة الناجحة/الفاشلة وإشعار الخادم إلى الخادم، مع متطلبات التحقق من التوقيع.
4. بيانات اختبار جديدة تُدخل مباشرة في تبويب Neoleap المحمي داخل إدارة متجر Manus، ولا تُرسل في المحادثة أو بلقطة شاشة.

## قواعد الأمان

- لا تُفعّل بيئة الإنتاج ولا تُنشأ عملية تحصيل إلا بعد اختبار انتقال ناجح في بيئة الاختبار وموافقة مستقلة من المالك.
- لا تُعرض مفاتيح أو كلمات مرور أو رموز تاجر في الواجهة أو في السجلات أو في استجابات API.
